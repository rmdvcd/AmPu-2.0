# Auditoría UI/UX/IX de escritorio y del asistente matemático · AmPu 3.0

**Fecha:** 28 de octubre de 2026. **Alcance:** exclusivamente `AmPu 3.0/`, PySide6/Qt 6 con motor NumPy/SciPy aislado de la UI, teoría Markdown + KaTeX local en QWebEngineView. **Destinos:** Windows, macOS y Linux; esta ejecución automatizada es Linux sin pila gráfica completa. Guías aplicadas: `desktop-ui-ux-ix.skill.md` y `math-desktop-assistant-ui-ux-ix.skill.md` facilitadas para esta revisión.

**Convención:** MUST = exigencia; SHOULD = mejora recomendable; MUST NOT = prohibición. Severidad Bloqueante/Alta/Media/Baja. `Verificado` significa prueba automatizada local; `Parcial` indica código implementado pero aceptación nativa incompleta; `Pendiente externo` requiere SO/hardware/tecnología asistiva no disponibles aquí. Las celdas «evidencia» remiten a código/pruebas, no a una validación visual no realizada. Las recomendaciones de hallazgos resueltos describen el cambio efectuado; las de pendientes son trabajo para la puerta de publicación, **no prestaciones afirmadas**.

## Asistente matemático: entrada, explicación y gráficos

**Tipo y límites:** asistente acoplable no modal, con dos superficies separadas. La pestaña **Cálculo explicado** solo acepta expresiones aritméticas numéricas del AST restringido en `core/estadistica/calculadora.py` (incluye algunas funciones y constantes). La pestaña **Fórmula LaTeX** recibe/pega código editable y lo renderiza localmente con KaTeX + MathML; **no interpreta, evalúa ni resuelve LaTeX**, y el proyecto no es un CAS. Salidas: resultado numérico/explicación textual, LaTeX, MathML cuando Chromium está disponible, sesiones JSON y fórmulas textuales en PDF. Los gráficos estadísticos pertenecen a las seis vistas analíticas, **no** se inventa una gráfica para cada fórmula arbitraria.

|---|---|---|---|---|

## Evidencia y puerta de publicación

1. En esta revisión: `python -m pytest --cov=ampu.core --cov-branch --cov-report=term -q`: **148 pruebas ejecutadas y aprobadas**, **1 módulo WebEngine omitido durante la importación**, cobertura **92 %** en `core/` con ramas (meta ≥85 %). Las pruebas Qt usan `QT_QPA_PLATFORM=offscreen` y bibliotecas suplentes **fuera del repositorio** únicamente para QWidget; la cobertura usa un SQLite temporal del entorno de tests. No equivalen a una prueba de Chromium/lector de pantalla.
2. `python scripts/validar_contra_scipy.py`: **121/121** comparaciones; `python -m ampu --verify-resources`: **57 lecciones, 31 imágenes, formatos XLSX/CSV/PNG/PDF/JSON** correctos; `git diff --check` sin incidencias. PyInstaller Linux creó ejecutables `--onedir` **y** `--onefile` con `--version`/`--verify-resources` correctos, **sin suplentes empaquetados**; esto no verifica la GUI.
3. **No dar por publicada la accesibilidad matemática o nativa** hasta la fila DUI-010: Chromium real, KaTeX/MathML, alto contraste y foco con NVDA/JAWS/VoiceOver, `--self-test`/`--gui-self-test` en cada SO. El sandbox carece de bibliotecas gráficas como `libxcb-dri3.so.0`; sin ellas, la omisión del test web y un paquete que verifica recursos **no certifican render visual**.
4. Mejoras SHOULD no bloqueantes explicitadas: reasignación de atajos, cancelación cooperativa de cálculos largos y navegación por nodos/Braille/dictado cuando se incorporen y prueben sus tecnologías. No se inventan capacidades del motor ni de Qt.
